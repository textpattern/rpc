'css_mode'

<p>The <a href="https://www.w3schools.com/css/default.asp">Cascading Style Sheets</a> standard is a slim, powerful language that allows you to centralize site-wide control of content presentation. Everything from fonts and colours to sizes and positions can be governed through <span class="caps">CSS</span>.</p>
<p>Ordinarily <span class="caps">CSS</span> data appears in the <code>head</code> section of an <span class="caps">HTML</span> document, or is stored in a text file linked to the document. Modern browsers parse this data in advance of displaying a page, and then cache the data for use on subsequent pages or site visits. As such, <span class="caps">CSS</span> can greatly reduce the download size of web pages: just one of many improvements  <span class="caps">CSS</span> formatting offers over older web design methods.</p>
<p>Textpattern offers two modes of maintaining style sheets for your pages.</p>
<p>In Manual <span class="caps">CSS</span> mode, you can create (or paste in) any style sheet information you like, right in the Textpattern interface. This allows for quick editing of styles without the clumsy bother of ftp uploading. Style sheets can be generated from scratch or by <span class="caps">WYSIWYG</span> website editors, and are found <a href="https://directory.google.com/Top/Computers/Programming/Internet/CSS/Sample_Style_Sheets/Layouts/">all over the web</a>.</p>
<p>In Automatic <span class="caps">CSS</span> mode, style sheet editing is taken to a sophisticated new level, using an editing interface and organizational method intended to make <span class="caps">CSS</span> parameters more readable and logical. Any existing style sheet can be &apos;poured&apos; into the editing interface and modified indefinitely.</p>
<p>In Automatic mode, <span class="caps">CSS</span> files are classified as either <em>layout</em> or <em>style</em>. Pages on a site can share or combine either type.</p>
<p>Layout files define large structural parameters, such as the number and size of columns on a page, headers and footers, &c.</p>
<p>Style files in turn govern parameters like typography, colour, and the finer methods of positioning (e.g. padding and margins and relationships between objects on a page) not defined in layout files.</p>

'section_category'
'Sections'
<p>Sections in Textpattern are perhaps best thought of as analogous to sections in a newspaper: each belong to the same publication, but each might feature a different layout, or a different style of article, and so on. </p>
<p>For most websites, only a bare minimum of sections need be created.</p>
<p>A likely scenario for a personal site, with three sections:</p>
<p><strong>archive</strong>: the section to which all articles that appear on the front page belong. Whenever a reader clicks on an article&apos;s permanent link (for example https://thissite/archive/123/), it will be displayed in the page layout assigned to this section. <p><strong>about</strong>: an &apos;about this site&apos; page, which differs from the front page and the <em>archive</em> section, in that it is more static, may have a different layout, and will likely contain only one article. The about section would be reached at https://thissite/about/.</p>
<p><strong>photos</strong>: A section whose differing layout (and possibly different <span class="caps">CSS</span>) would display photos instead of articles.</p>
<p>Note that a special hidden &apos;section&apos; always exists, named <strong>default</strong>. Using the layout called &apos;default&apos; as well as the <span class="caps">CSS</span> called &apos;default&apos;, this is what makes up the front page of your site. </p>

'send_lastmod'
'Send Last-Modified Header'
<p>When set, Textpattern will read a visitor&apos;s <acronym title="HyperText Transfer Protocol">HTTP</acronym> <code>If-Modified-Since</code> header (if one exists) and compares it to the last site update. If nothing has changed since the visitor last loaded the page (i.e., if the timestamp the browser sends is the same as the last site update), then a header is sent back instructing the visitor&apos;s browser to use its cached version of the page.</p>
<p>This can reduce bandwidth consumption, page load times, and reduce the load on the webserver.</p>

'url_mode'
'URL Mode'
<p>Governs how permanent links to archived articles will appear. </p>
<p>?=messy mode is the most straightforward; it will work without you having to do much mucking about. In this mode URLs for archived articles on your site will look like this:</p>

<code>https://www.yoursite.com/index.php?id=123</code>

<p>/clean/ mode is a little trickier, but it makes URLs that are elegant and easier to remember. Here are the steps to make /clean/ mode work:</p>
<p>You must have &apos;Use sections&apos; set in Site Preferences</p>
<p>Your site must be on a Unix-based server running Apache, or on a Windows server running  <span class="caps">PHP</span> as an Apache module</p>
<p>For every section you have on your site (including the default section called &apos;article&apos;), place a text file with the exact same name in your root web directory, containing the following bit of code, replacing <span class="caps">SECTION</span>_NAME with the section&apos;s actual name:</p>

<code><br />
&lt;?php<br />
include "./textpattern/config.php"; <br />
$s = "SECTION_NAME";<br />
include $txpcfg["txpath"]."/publish.php";<br />
textpattern();<br />
?&gt;<br />
</code>

<p>Next, with a text editor create or open an existing file in your web root called <code>.htaccess</code> and paste the following inside:</p>

<code><br />
&lt;Files SECTION_NAME&gt; <br />
ForceType application/x-httpd-php <br />
&lt;/Files&gt; <br />
</code>

<p>again, replace <span class="caps">SECTION</span>_NAME with the section&apos;s actual name.</p>
<p>Once you select /clean/ url mode in Site Preferences, your permanent link urls will look more familiar:</p>

<code>https://www.example.com/article/123/</code>

'warn_register_globals_or_update'
'Turn register_globals off or update to a newer PHP version'
<p>Recently a severe vulnerability was discovered in PHP. <a href="https://www.hardened-php.net/advisory_202005.79.html">The security advisory</a> says:</p>

	<blockquote>
	<p>can lead to unexpected behaviour of PHP applications, which can lead to execution of remote PHP code in many situations.</p>
	</blockquote>

<p>Vulnerable versions are PHP4-versions <= 4.4.0 and PHP5-versions <= 5.0.5. You should either update to newer versions or make sure that register_globals is turned off.</p>
<p>You can turn off register_globals in the php.ini file. If you are in a hosted environment, you may have an option in your hosting control panel for it (ask your host). When using mod_php (php as an apache module), it is also possible to turn register_globals off via .htaccess. Uncomment the following line from your .htaccess:</p>

<code>php_value register_globals off</code>

'plugin_cache_dir'
'Preferences: Plugin cache directory path'
<p>This setting is mainly used for plugin developers. When specified, you can put the plugin source file (not compiled) in this directory and Textpattern will load it automatically, so you can easily edit the plugin and immediately see the effect it has without having to install/activate the plugin. <strong>Beware</strong> though that by using this method, a broken plugin (which fails to compile) may also break Textpattern!</p>
<p>It is recommended that you load plugins through the standard &apos;Plugins&apos; administration panel on a production site, rather than using the plugin cache directory.</p>
<p class="alert-block information"><strong>Note:</strong> Do not specify the same directory for both &apos;temporary&apos; and &apos;plugin cache&apos;, as this will cause problems (Textpattern would try to run the contents of temporary log files as plugins).</p>

<p>Sections in Textpattern are perhaps best thought of as analogous to sections in a newspaper: each belong to the same publication, but each might feature a different layout, or a different style of article, and so on. </p>

<p>A likely scenario for a personal site, with three sections:</p>
<p><strong>archive</strong>: the section to which all articles that appear on the front page belong. <p><strong>photos</strong>: A section whose differing layout (and possibly different <span class="caps">CSS</span>) would display photos instead of articles.</p>
